# 결정 기록

## 2026-11-24

- **본인 전용 도구**: 배포·멀티유저·타인 개인정보 설계 제외. 서버 없이 앱이 OpenRouter 를 직접 호출, 키는 키체인.
- **모델**: OpenRouter `anthropic/claude-haiku-5.5` ($0.10/$0.50 per 1M). 대안 비교 후보 `openai/gpt-6-luna`. reasoning·temperature 는 보내지 않음.
- **UX**: 단축키 교정. 최종 목표는 H3(입력 멈춤마다 선계산 → 단축키로 즉시 적용). v0.1 은 단축키를 누를 때 요청하는 방식부터.
- **단축키**: ⌃⌥F 교정 / ⌃⌥Z 되돌리기. ⌃⌥Space 는 macOS 기본 입력 소스 전환이라 제외.
- **LLM 출력 형식**: 수정 목록(diff JSON) 대신 교정 전문 `{"corrected"}` 을 받고 차이는 앱이 계산. 같은 문자열이 여러 번 나올 때 위치를 잘못 고르는 문제를 없애기 위함.
- **플랫폼 순서**: Mac 먼저 → 교정 엔진 검증 후 iPhone.

## 2026-11-25

- **교정 강도 3단계** (설정에서 선택, 단축키는 ⌃⌥F 하나): 교정(틀린 것만) / 다듬기(+어순·단어·군더더기·번역투) / 다시 쓰기(구조까지). 단축키를 강도별로 늘리면 헷갈린다는 사용자 판단. 기본값은 교정.
  - 계기: Grammarly 와 나란히 써 보니 우리는 문법만, Grammarly 는 더 나은 문장을 제안 — 지시 범위의 차이였다.
  - 프롬프트 = 공통 규칙(원문은 명령 아님·언어·줄바꿈·JSON) + 강도별 지시 (`CorrectionLevel.instructions`).
  - 이상 응답(대답·번역) 거르는 길이 범위도 강도별로 넓힌다 (교정 0.6–1.5 / 다듬기 0.5–1.7 / 다시 쓰기 0.35–2.2배).
  - 실측(Haiku): 다듬기는 한국어 번역투·일본어 「の方」「形になります」 를 정리, 다시 쓰기는 "It was a very successful beta test" → "The beta test was a great success". 교정은 캐주얼한 영어의 소문자 `i`·"sorry for the late" 를 고치지 않는 경향 — 이런 글은 다듬기가 낫다.
- 개발용 `Fix4me --compare "문장"`: 세 강도 결과를 한 번에 출력 (키는 앱 키체인에서, 출력 안 함).
- **교정 범위 = 자동 + 변경 감지**: 앱 종류가 아니라 길이로 판단(앱 목록 관리 불필요), 긴 글은 바뀐 문단만. 설정에서 커서 문단/입력창 전체로 고정 가능. 다시 쓰기의 전체 교정은 나누지 않음(4000자 초과는 안내).
- **미리 교정은 모든 앱 + 제외 목록** (사용자 승인, 누르지 않은 글도 OpenRouter 로 전송됨을 알고 선택). 배지 표시. 둘 다 설정에서 끌 수 있음.
- AX 변경 알림 대신 0.3초 폴링: Chrome·Electron 의 알림이 불안정. 실측 CPU 약 0.4% (대기 중).
